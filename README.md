# Trade Activity

Локальная история сделок T‑Bank с группировкой позиций, планами и отчётом по месяцам и дням.

## Структура

```text
backend/
  api/              HTTP: торговля, планы, дневник, настройки
  migrations/       перенос старого дневника в планы
  services/         сценарии: позиции, планы, синхронизация, экспорт
  domain/           расчёт позиций, планов и правила определения выхода
  storage/          SQLite, обновление схемы, планы и вложения
  brokers/          клиент T-Bank
  config.py         пути и локальная конфигурация
frontend/src/
  app/              маршрутизация страниц, routes.json и левое меню
  features/
    trading/        позиции, таблица, колонки, API и стили
    plans/          планы, результат, скриншоты и привязка позиций
    reports/        отчёт торговли по месяцам и дням, API и стили
    data-transfer/  импорт TradingView и экспорт JSON
    settings/       справочник связок инструментов и поиск через MCP
  shared/           общие компоненты, HTTP-клиент и форматирование
  main.jsx          точка входа React
tests/              проверки домена, API планов, миграции и дневника
data/               скриншоты планов (не в Git)
app.py              запуск Flask
pyproject.toml      зависимости Python
config.json         локальные настройки и токен (не в Git)
trade_activity.sqlite3  локальные данные (не в Git)
```

HTTP-обработчики вызывают сценарии из `services`. Сценарии используют расчёты
из `domain`, хранилище `storage` и при синхронизации — клиент из `brokers`.
Расчёты не обращаются к Flask, базе или сети. Пути к конфигурации и базе задаются
от корня проекта и не зависят от расположения модулей.

На фронтенде каждый раздел содержит свои компоненты, запросы и стили. В `shared`
находится код, который нужен нескольким разделам. Нового брокера следует добавлять
в `brokers`, а синхронизацию подключать через `services`; UI работает с общими позициями.
Приложение по-прежнему запускается одним процессом Flask (и Vite в режиме разработки).

## Первый запуск

Нужны Python 3.10+ и Node.js 22.12+.
Все команды выполняются из корня проекта, если не указано иначе.
Python-зависимости описаны в `pyproject.toml`. Установка через `pip install -e .`
связывает окружение с исходниками проекта; приложение запускается из этого checkout.

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
cd frontend
npm ci
npm run build
cd ..
```

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

Добавьте read-only токен T‑Invest API в `config.json`:

```json
{
  "tbank_token": "ваш токен",
  "port": 8000
}
```

Запуск:

```bash
# macOS / Linux
.venv/bin/python app.py
```

```powershell
# Windows PowerShell
.venv\Scripts\python.exe app.py
```

Откройте <http://127.0.0.1:8000>.

## Торговля и дневник

Левое меню сворачивается; его состояние сохраняется в браузере.

- **Торговля** (`/`) — факты по позициям и ссылка «Открыть план» / «Создать план».
- **Отчёт торговли** (`/reports`, старый адрес `/monthly`) — сводка по закрытым позициям
  по месяцам или дням.
- **Дневник трейдера** (`/journal`) — планы. Вкладка «План»: платформа, направление,
  тикер, вход, тейк, стоп, описание и скриншоты. Вкладка «Исполнение»: таблица
  позиций (вход/выход) и поле результата. Вкладка «Без плана» показывает позиции,
  которые ещё не разобраны. Числа входа, тейка и стопа принимают точку и запятую; в SQLite они
  хранятся как `REAL`, и после сохранения форма показывает число в формате базы.

Позиции остаются фактами из синхронизации или импорта, а план — авторским слоем.
Один план может содержать несколько позиций; одна позиция привязывается не более
чем к одному плану. Уровни плана имеют приоритет над старыми `position_notes`,
поэтому правка стопа или тейка сразу меняет оценку выхода и отчёт. Факты сделок
при этом не изменяются.

Скриншоты хранятся файлами в `data/attachments/`, в SQLite — только метаданные.
Поддерживаются PNG, JPEG и WebP до 15 МБ. Файлы перетаскиваются в Dropzone или
выбираются кликом; изображение можно вставить из буфера обмена. Поле «Результат»
хранится в плане; итоговая таблица считается по привязанным позициям.
Стоп и тейк — записи плана; они не выставляют заявки брокеру.

Причина выхода оценивается автоматически по уровням плана и ценам всех исполнений
с учётом лонга/шорта. Это предположение, а не подтверждённый тип заявки.
Если стоп или тейк не определён, по правилу журнала показано «Вышел руками»
(в экспорте источник `default_rule`); разные способы частичного закрытия
дают «Смешанный выход». Оценка пересчитывается после сохранения плана и входит в JSON-экспорт.
Алгоритм находится в `backend/domain/journal.py` и не зависит от Flask или SQLite.
Старые значения скрытых полей «Эмоции и дисциплина» и «Выводы» в существующей базе сохраняются.

### Перенос старого дневника в планы

Таблицы планов добавляются в SQLite при запуске, старые `position_notes` не меняются.
Миграция создаёт по одному плану на запись дневника, сохраняет текст и уровни
байт-в-байт и не пишет событий переноса. Оценка выхода и отчёт при этом не меняются.

По умолчанию команда работает в режиме проверки и ничего не записывает:

```bash
.venv/bin/python -m backend.migrations.journal_to_plans
```

Применение с резервной копией, проверками и откатом при расхождении:

```bash
.venv/bin/python -m backend.migrations.journal_to_plans --apply
```

Для проверки на копии базы укажите `--database /path/to/copy.sqlite3`. Повторный
запуск идемпотентен. Перед `--apply` остановите Flask, чтобы не было параллельной
записи. На текущей локальной базе миграция уже выполнена: 214 записей старого
дневника стали 214 планами с привязанными позициями; исходные `position_notes`
сохранены. Резервная копия создаётся рядом с базой (`*.sqlite3.bak-*`).

## Настройки инструментов

В разделе **Настройки → Основные инструменты** (`/settings`) доступна таблица
из семи инструментов: контракты и средние стопы из пользовательского списка,
ссылки на графики склеек и базовых активов в TradingView. В валютной секции —
юань и доллар/рубль (Si); средний стоп для обоих — 50–100 пунктов (0,5–1 рубль) по указанным пользователем значениям. Данные списка находятся в
`frontend/src/features/settings/mainInstruments.js`; таблица не требует подключения к Т-Банку.

На вкладке **Связки инструментов** создаются связки:
инструмент прогноза, биржа прогноза, инструмент работы, биржа работы.
«Добавить связку» открывает поиск по тикеру или названию; биржа заполняется
из выбранного инструмента. Режим торгов показывается рядом с тикером, чтобы
различать одинаковые обозначения. Для фьючерсов показывается экспирация.

Поиск и получение реквизитов выполняются сервером приложения через официальный
[T-Invest MCP](https://developer.tbank.ru/invest/mcp) по адресу
`https://invest-public-api.tbank.ru/mcp`, с `tbank_token` из `config.json`.
Настройки MCP редактора для работы страницы не требуются. Клиент поддерживает
только поиск и чтение реквизитов акций, фьючерсов, облигаций, валют, фондов и опционов.
Токен остаётся на сервере и не попадает в браузер или записи справочника.

Связки сохраняются в SQLite вместе с идентификаторами поставщика, режимом торгов
и снимком реквизитов. Они доступны без сети. «Обновить» получает свежие реквизиты
обоих инструментов; при ошибке сохраняется предыдущий снимок. Время получения
видно при наведении на биржу. Обновление не заменяет истёкший контракт другим:
для перехода на новый контракт используйте «Изменить».

TradingView MCP пока не интегрирован. Поле стопа в справочнике пока не добавлено:
его смысл и единицы измерения требуют определения отдельно от стопов в плане.

## Импорт TradingView Paper Trading

Откройте раздел «Импорт и экспорт» (`/data-transfer`), перетащите CSV-файлы
в зону загрузки Mantine Dropzone или нажмите на неё для выбора, затем нажмите
«Импортировать». Обязателен файл `paper-trading-trade-history…csv`; можно выбрать
все шесть выгрузок одновременно (до 20 МБ). История заявок уточняет время исполнения,
история баланса — точный PnL и валюту цены. Снимок открытых позиций, текущие заявки
и текстовый журнал активности не создают дополнительные сделки.

Название демо-счёта определяет отдельный счёт в приложении. При повторных загрузках
используйте то же название; для другого счёта или после сброса Paper Trading — новое.
Повторный импорт обновляет позиции без дублей и сохраняет записи дневника. Закрытая
позиция не откроется заново при загрузке старой истории. Отсутствующие в файле позиции
не удаляются. Данные T-Bank не изменяются.

PnL и комиссия берутся из отчёта TradingView, без пересчёта стоимости фьючерсного пункта.
Суммы разных валют отображаются раздельно в отчёте торговли. Без истории баланса
валюта цены может отсутствовать, PnL остаётся в валюте отчёта. Время сохраняется как
в CSV: TradingView не указывает в этих полях часовой пояс. История сделок округляет
время до минуты и агрегирует входы; журнал отдельных исполнений из неё не восстанавливается.
Поддерживается предоставленный английский формат CSV с парными Entry/Exit, включая
Exit с датой Open. Неоднозначные частичные выходы с повторяющимся входом отклоняются
до записи в базу. Автоматической связи с аккаунтом TradingView нет.

Импортированные позиции хранятся в `imported_positions` отдельно от исполнений T-Bank
и доступны в торговле, дневнике, JSON-экспорте и отчётах.

## Зачем оставлены тесты

`test_exit_reason.py` проверяет лонг/шорт, стоп и тейк, частичные выходы и числа
с пробелами — в том числе исправленную ошибку со стопом `214 550`.
`test_journal.py` проверяет сохранение разбора, обновление старой схемы без потери
заметок и неизменность торговых фактов. `test_plans_api.py` проверяет создание
плана из позиции, привязку и отвязку, результат, скриншоты и приоритет уровней плана.
`test_plans_migration.py` проверяет перенос 1:1, резервную копию, сохранность
текста и идемпотентность. При перемещении кода эти проверки помогают сразу
обнаружить изменение поведения. Они используют стандартный `unittest`, временную
базу и не требуют токена, сети или дополнительных пакетов.

Запуск:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

## Два винрейта

В отчёте торговли и JSON-экспорте итоговый винрейт — доля прибыльных после
комиссии среди всех закрытых позиций (безубыточные входят в знаменатель).
Чистый винрейт — тейки / (тейки + стопы), независимо от знака финансового результата.
Ручные, смешанные и неопределённые выходы исключены из чистого винрейта и посчитаны
отдельно. Причины пока оцениваются по уровням плана и ценам выходов.
Ручной выход по прежнему правилу `default_rule` при недостатке данных для статистики
считается неопределённым. При пустой выборке показатель отсутствует (`null`, в UI «—»).
Общий процент за период вычисляется из суммарных количеств, а не средних месячных процентов.

## Правила разделения кода

- `*Page.jsx` собирает экран; загрузка, действия и жизненный цикл находятся
  в хуке соответствующего раздела рядом со страницей.
- Компоненты выделяются по самостоятельной ответственности: форма импорта,
  таблица отчёта, форма плана, таблица позиций. Небольшие фильтры остаются
  на странице. Локальное состояние формы остаётся внутри формы. Общие фильтры
  торговли и экспорта находятся в `shared/positions`.
- Настройки колонок обслуживает `usePositionColumns`. Запись настроек через API
  последовательна: поздний ответ предыдущего сохранения не отменит следующий сброс.
- Чистые вычисления находятся в `model.js`; общий код переносится в `shared`
  только при использовании несколькими разделами. API-модули не зависят от React.
- При смене фильтров и уходе со страницы запросы чтения отменяются через
  `AbortController`; устаревшие ответы игнорируются.
  Чтение сохранённых фильтров отчёта само по себе не вызывает запись.
- Страницы подключаются через `React.lazy`: код раздела загружается при открытии.
  Новый маршрут добавляется в `frontend/src/app/routes.json`, компонент — в таблицу `pages` в `App.jsx`.
  Список маршрутов используется только фронтендом. Flask раздаёт содержимое `frontend/dist`
  и возвращает `index.html` для клиентских путей; неизвестную страницу показывает React.
  Отсутствующие API и статические файлы возвращают 404. Исходники фронтенда сервер не читает.
- Цвета и скругления берутся из темы Mantine. Общие стили находятся в `shared`,
  стили отдельных разделов — рядом со страницами.
- На сервере HTTP-обработчики передают сценарии сервисам. Импорт находится
  в `services/imports.py`, отчёт — в `services/reports.py`, планы — в
  `services/plans.py`; зависимости направлены `plans → journal → trading`,
  `reports → journal → trading`, без обратного импорта.
- Скриншоты планов лежат в `data/attachments/`; база хранит только путь и
  метаданные. Файл удаляется вместе с записью вложения.
- `storage.database.transaction()` управляет транзакцией и закрывает соединение
  при успехе и исключении. Отбор импортированных позиций по счетам выполняется SQL
  с индексом до разбора JSON. Доменный код не обращается к хранилищу.

Проверки после изменения:

```bash
.venv/bin/python -m unittest discover -s tests -v
npm --prefix frontend test
npm --prefix frontend run build
```

Frontend-тесты используют встроенный `node:test`: проверяют взвешенный расчёт
винрейта, разделение валют и порядок сохранения настроек при ошибке запроса.
Сборка не заменяет проверку пользовательских сценариев в браузере.

## Единый стиль кода

Python форматируется и проверяется Ruff, JavaScript/JSX/CSS/JSON — Prettier.
Настройки закреплены в `pyproject.toml`, `frontend/.prettierrc.json` и `.editorconfig`.
Отступы: 4 пробела в Python, 2 — на фронтенде; ширина строки — 100 символов.
Python-импорты сортирует Ruff. На фронтенде сначала идут внешние зависимости,
затем общие модули, модули раздела и стили. Стили Mantine подключаются перед
стилями приложения, чтобы локальное оформление имело приоритет. Комментарии объясняют причины и ограничения.

Установка инструментов разработки:

```bash
.venv/bin/python -m pip install -e '.[dev]'
npm --prefix frontend ci
```

Форматирование:

```bash
.venv/bin/ruff check backend tests app.py --fix
.venv/bin/ruff format backend tests app.py
npm --prefix frontend run format
```

Полная проверка перед завершением изменений:

```bash
.venv/bin/ruff check backend tests app.py
.venv/bin/ruff format --check backend tests app.py
npm --prefix frontend run format:check
.venv/bin/python -m unittest discover -s tests
npm --prefix frontend test
npm --prefix frontend run build
git diff --check
```

Проверки маршрутизации используют временную сборку без исходников фронтенда:
клиентские пути получают приложение, а отсутствующие API и статические файлы — 404.
Frontend-тесты также проверяют обработку HTTP-ошибок, JSON-запись и фильтры нескольких счетов.
